# 云开发部署手册（上线前必读）

开源仓库默认是**离线演示配置**：`demoMode: true`、`useCloud: false`、`cloudEnv: ''`，导入微信开发者工具即可看到完整演示数据。

要接云开发，需要你准备：自己的小程序 AppID、已开通的云开发环境 ID。

> **部署检查清单**
> 1. `project.config.json` 的 `appid` 改成你的 AppID。
> 2. `config.js` 填 `cloudEnv`，按需把 `demoMode` 改 `false`、`useCloud` 改 `true`，并填写 `operatorName` / `supportPhone`。
> 3. 右键 `cloudfunctions/login`、`cloudfunctions/sync` →「上传并部署（云端安装依赖）」。
> 4. 用 `setup` 云函数一次性创建 14 个集合，随后删除该函数。
> 5. 集合权限设为「所有用户不可读写」（客户端只走云函数）。
> 6. 在控制台为 `teamId` / `openid` / `inviteCode` 建索引。
> 7. 隐私保护指引 / 服务类目 / 真机预览 / 提审在 mp 后台完成。

> `cloudfunctions/setup` 只是一次性建表工具（已移除删除数据能力，只剩幂等建表）。
> **提审前请在控制台删除该函数**，避免留下无用的公开入口。

## 真机验收流程（提审前逐项走一遍）

1. **清缓存编译**：工具 → 清除全部缓存 → 编译，确认首屏是登录页（不是演示数据）
2. **一键登录**：登录页点「微信一键登录」，应直接进工作台
3. **建团队**：没有团队时 → 创建公司团队 → 拿到 6 位邀请码
4. **换设备加入**：另一台手机登录 → 输入邀请码 → 能看到同一批数据
5. **主链路**：录入客户 → 报价 → 转合同 → 开项目（自动生成 11 个工序）→ 节点开工/完工 → 登记收款 → 看报表数字变化
6. **巡检传照片**：项目 → 巡检 → 新增 → 选图上传，确认云端返回 fileID 且再次进入能看到图
7. **弱网**：切成 4G，重复 3、5 两步，观察是否有卡死或空白
8. **退出再进**：我的 → 退出登录 → 微信一键登录，确认还能回到原团队

## 多公司（多租户）怎么放

**不需要给每家公司建库或建集合。** 14 个集合全公司共用，靠 `teamId` 隔离：

- 每条业务记录都带 `teamId`，`store.list()` 自动按当前团队过滤
- 云函数 `sync` 每次调用都先校验「你是不这个团队的成员」，越权读写直接拒绝
- 推送时还会二次校验 `rec.teamId === teamId`，防止伪造

新增一家公司 = 对方在小程序里「创建团队」，拿到邀请码，员工凭码加入。**不需要你动数据库。**

索引的作用只是提速（数据上万条后明显）。控制台按《第四步》建一次即可，之后新增公司不用再建。

## 微信一键登录

登录页已支持「微信一键登录」，原理：

1. 客户端 `wx.cloud` 拿到当前微信 openid
2. 调 `sync` 云函数的 `whoami`，云端用 `users` 集合按 `openid` 反查成员
3. 找到就把成员 + 团队写回本地并拉取数据，直接进工作台

| 情况 | 结果 |
|---|---|
| 有成员、有团队 | 直接进工作台 |
| 有微信但没团队 | 引导去「创建 / 加入团队」 |
| 云端没有该 openid | 同样引导去创建 / 加入团队 |
| 团队建在别的微信号下 | 认不出，退回「手机号 + 初始密码」登录 |

> 首次创建/加入团队后会自动把 openid 写到云端，之后换手机也能一键登录。

## 第一步：确认环境 ID 已生效

1. 微信开发者工具打开本项目
2. 顶部点「**云开发**」，确认能看到你在 `config.js` 填写的环境
3. 若 `project.config.json` 里的 `appid` 不是你本人的（或仍是 `touristappid`），先改成本人 AppID

## 第二步：部署两个云函数

在开发者工具左侧文件树里展开 `cloudfunctions` 目录，分别右键：

1. 右键 `cloudfunctions/login` → 「**上传并部署：云端安装依赖**」
2. 右键 `cloudfunctions/sync` → 「**上传并部署：云端安装依赖**」

部署成功标志：两个函数在云开发控制台「云函数」列表里出现，状态「正常」。

## 第三步：创建 14 个集合

云开发控制台 → 「数据库」→ 逐个「新建集合」：

```
teams
users
customers
follows
quotes
contracts
projects
inspections
changes
receipts
expenses
materials
aftersales
todos
```

> 共 14 个（上面 14 个，含 teams/users 两个基础集合）。

每个集合的权限建议选「**仅创建者可读写**」（因为我们所有读写都走云函数，
云函数以管理员身份访问，前端不直接操作数据库，安全性最高）。

## 第四步：为查询加索引（否则大表查询报错/超限）

数据库 → 每个集合 → 「索引管理」→ 新增索引：

| 集合 | 字段 | 说明 |
|---|---|---|
| 所有业务集合 | `teamId` | 按团队查询 |
| users | `teamId` + `openid` | 成员身份校验 |
| teams | `inviteCode` | 邀请码查询 |

## 第五步：编译验证

1. 菜单「工具 → 清除缓存 → 清除全部缓存」
2. 点「编译」
3. 流程自测：
   - 首次打开 → 登录页是「创建/加入团队」（不是演示账号）
   - 创建团队 → 拿到邀请码
   - 真机预览（另一台设备）→ 输入邀请码加入 → 能看到团队客户

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 加入团队提示「邀请码无效」 | `sync` 云函数没部署成功，或 `teams` 集合没建 |
| 云同步无反应、各设备数据不同步 | 云函数部署失败 / 集合权限不是「仅创建者可读写」 |
| 报 `cloud init` 错误 | `config.js` 的 `cloudEnv` 和实际环境 ID 不一致 |

---

## 重要提醒

- **AppSecret 不要发给任何人**，本项目用不到它。
- 团队共享依赖云开发；未部署云函数前，换设备数据不互通。
- 上线前把 `config.js` 的 `demoMode` 保持 `false`（当前已是）。
